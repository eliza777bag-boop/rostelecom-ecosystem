# Экосистема коммерческого блока

Прототип для хакатона Ростелеком 2026. Одна веб-страница с тремя модулями:

1. **Радар присутствия** — карта компаний Ростовской области (Leaflet), тепловая карта, фильтры, «белые пятна», экспорт в CSV.
2. **Инвестиционный навигатор** — 63 инвестпроекта: фильтры, таймлайн, карточка проекта, экспорт в CSV, кнопка «Сформировать КП».
3. **Калькулятор сделок** — расчёт минимальной и оптимальной цены коммерческого предложения.

Вход защищён **двухфакторной аутентификацией (2FA)**: логин + пароль, затем 6-значный код из Google Authenticator или Microsoft Authenticator. Пароль и код проверяет сервер (`backend/server.py`), а не браузер.

## Как устроена защита (простыми словами)

Раньше сайт был набором файлов, и любой, кто знал адрес, мог открыть их все. Проверка пароля в JavaScript ничего бы не дала: такой код виден каждому, его можно отключить в браузере. Поэтому добавлен небольшой **сервер на Python**, и теперь файлы отдаёт только он:

1. Пока вы не вошли, сервер на любую страницу отвечает «иди на /login», а на файлы (`js/…`, `data/radar_data.csv`) — ошибкой 401. Ни страница, ни данные компаний не уходят в браузер.
2. **Шаг 1.** Вы вводите логин и пароль. Сервер сравнивает пароль с **хешем** (необратимым «отпечатком»). Сам пароль нигде не хранится.
3. **Шаг 2.** Вы вводите 6-значный код из приложения на телефоне. В телефоне и на сервере лежит один и тот же секретный ключ. Из ключа и текущего времени обе стороны вычисляют код (стандарт TOTP, RFC 6238). Код меняется каждые 30 секунд и принимается только один раз.
4. Только после обоих шагов сервер выдаёт **сессию**: случайный идентификатор в cookie, недоступный JavaScript (`HttpOnly`). Сессия заканчивается после 30 минут бездействия, через 8 часов или по кнопке «Выйти».

Почему Python и без библиотек: Python скорее всего уже стоит у вас (или ставится за 2 минуты), а без внешних пакетов нечего устанавливать, нечему ломаться и нечего обновлять. База данных не нужна: пользователь один, его данные лежат в `private/auth.json` или в переменных окружения хостинга.

Дополнительно: пять неверных попыток для логина (или десять с одного IP) блокируют вход на 15 минут, после пяти неверных кодов нужно заново вводить пароль, запросы с чужих сайтов отклоняются, файлы `backend/`, `private/`, `README.md`, `.gitignore` сервер не отдаёт никогда.

## Как запустить на своём компьютере (Windows)

**Нужен Python 3.8 или новее.** Проверьте в PowerShell: `py --version`. Если команда не найдена, скачайте Python с python.org и при установке поставьте галочку «Add python.exe to PATH».

1. Распакуйте архив. Положите свой `radar_data.csv` в папку `data/` (если хотите, чтобы Радар загружался сам).
2. Откройте папку `ecosystem-commercial` в Проводнике, в адресной строке напишите `powershell` и нажмите Enter. Откроется терминал сразу в этой папке.
3. Один раз настройте вход (см. следующий раздел): `py backend\setup_2fa.py`
4. Запустите сервер: `py backend\server.py`
5. Откройте в браузере **http://localhost:8000**. Вы попадёте на страницу входа.
6. Остановить сервер: в окне PowerShell нажмите `Ctrl+C`.

Если вместо `py` у вас работает `python`, используйте его. На macOS/Linux: `python3 backend/setup_2fa.py`, `python3 backend/server.py`.

Открывать `index.html` двойным щелчком по-прежнему можно (модули работают, CSV выбирается кнопкой), но **в таком режиме входа нет**: файлы просто лежат на вашем диске. Защита работает только когда сайт открыт через сервер.

## Первоначальная настройка 2FA

1. Установите на телефон **Google Authenticator** или **Microsoft Authenticator**.
2. В PowerShell в папке проекта выполните `py backend\setup_2fa.py`.
3. Введите логин (латиницей, например `admin`) и пароль не короче 10 символов. При вводе пароля символы не отображаются. Это нормально.
4. Скрипт покажет **ключ** (32 символа группами по 4). Добавьте его в приложение:
   - Google Authenticator: «+» → «Ввести ключ настройки» → название любое (например «Экосистема РТ») → ключ → тип «По времени».
   - Microsoft Authenticator: «+» → «Другая учётная запись (Google, Facebook и т. д.)» → «Ввести код вручную».
5. Введите в скрипт 6-значный код из приложения. Если код верный, данные сохранятся в `private/auth.json`.
6. Запустите сервер и войдите.

QR-код скрипт не рисует: для этого нужна внешняя библиотека, а отправлять ключ в онлайн-генераторы QR нельзя. Ручной ввод ключа поддерживают оба приложения.

**Сменить пароль или телефон:** запустите `setup_2fa.py` ещё раз с тем же логином. Старый ключ перестанет работать, в приложении удалите старую запись.
**Потеряли телефон:** то же самое. Доступ к компьютеру с проектом = возможность сбросить 2FA, поэтому храните папку `private/` в надёжном месте.

Если код всё время «неверный»: в телефоне и на компьютере должно стоять **автоматическое время**. Расхождение больше ~30 секунд ломает коды.

## Проверка: без пароля и кода войти нельзя

### Автотесты (1 минута)

```
py backend\test_auth.py
```

Тесты поднимают отдельный сервер с временным тестовым пользователем (ваш `private/auth.json` не трогается) и проверяют 23 сценария. В конце должно быть `OK`.

### Проверка руками в браузере

Лучше в окне «Инкогнито», чтобы не мешали старые cookie.

| 6 | После шага 1 (не вводя код) открыть в новой вкладке http://localhost:8000/data/radar_data.csv | «Требуется вход»: одного пароля мало |
| 7 | Ввести верный код | Открывается сайт, справа вверху логин и «Выйти» |
| 8 | Проверить модули: Радар (карта, фильтры, тепловая карта, «Загрузить CSV»), Навигатор (фильтры, таймлайн, «Сформировать КП»), Калькулятор | Всё работает как раньше |
| 9 | Выйти и попробовать войти снова **тем же** кодом (пока он не сменился) | Код не принимается: каждый код одноразовый |
| 10 | Нажать «Выйти», затем кнопку «Назад» в браузере | Перебрасывает на вход |
| 11 | 5 раз ввести неверный пароль | Сообщение о блокировке на 15 минут |
| 12 | Открыть http://localhost:8000/private/auth.json и /backend/server.py | «Не найдено» |

Сервер пишет в окно PowerShell каждую удачную и неудачную попытку входа (без паролей и кодов).

## Публикация в интернете

**GitHub Pages для этой версии не подходит.** Pages только раздаёт файлы и не запускает Python. Если выложить туда проект, страница откроется **без всякого входа**: 2FA там не работает. Это допустимо только как открытая демо-витрина без данных (CSV там и так нет). Для жюри нужен хостинг, который запускает Python-программу.

Подойдёт любой сервис, который умеет запускать Python-приложение, например **Render** (render.com, есть бесплатный тариф), Railway, Amvera, Timeweb Cloud или свой VPS. Ниже пример для Render. Интерфейс сервисов меняется, поэтому названия кнопок сверяйте с их документацией.

1. Загрузите проект в **приватный** репозиторий GitHub. Благодаря `.gitignore` туда **не попадут** `private/`, `data/*.csv`, `backup/`. Перед первым коммитом проверьте список файлов: ни `auth.json`, ни `radar_data.csv` в нём быть не должно.
2. На своём компьютере выполните `py backend\setup_2fa.py --env`. Скрипт проведёт ту же настройку с телефоном, но вместо файла покажет три строки: `AUTH_USERNAME=…`, `AUTH_PASSWORD_HASH=…`, `AUTH_TOTP_SECRET=…`.
3. На Render: New → **Web Service** → выберите репозиторий.
   - Runtime: Python. Build Command: оставьте пустым (или `echo ok`, если поле обязательное).
   - Start Command: `python backend/server.py`
4. В разделе **Environment** добавьте переменные:

   | Переменная | Значение | Зачем |
   |---|---|---|
   | `AUTH_USERNAME` | из шага 2 | логин |
   | `AUTH_PASSWORD_HASH` | из шага 2 | хеш пароля |
   | `AUTH_TOTP_SECRET` | из шага 2 | ключ 2FA (секрет!) |
   | `HOST` | `0.0.0.0` | принимать подключения из интернета |
   | `COOKIE_SECURE` | `1` | cookie только по HTTPS |
   | `TRUST_PROXY` | `1` | правильно определять IP за прокси хостинга (для блокировки подбора) |

   `PORT` Render задаёт сам, сервер его читает.
5. CSV с компаниями в репозиторий не кладите. Варианты:
   - ничего не делать: после входа пользователь нажимает «📂 Загрузить CSV», файл обрабатывается только в его браузере и на сервер не отправляется;
   - или загрузить файл как секретный файл хостинга (у Render это «Secret Files», файл окажется в `/etc/secrets/radar_data.csv`) и добавить переменную `RADAR_CSV_PATH=/etc/secrets/radar_data.csv`. Тогда сервер будет отдавать его только вошедшим пользователям.
6. Откройте выданный адрес `https://….onrender.com` и пройдите проверки из таблицы выше.

Что важно знать про хостинг:
- Сайт должен открываться **только по HTTPS** (на Render это так по умолчанию). Без HTTPS пароль и cookie можно перехватить.
- Сессии хранятся в памяти сервера. После перезапуска или «засыпания» бесплатного сервиса все выходят из системы, и нужно войти заново. Для прототипа это нормально.
- Если после публикации шаг 1 отвечает «Запрос с чужого сайта отклонён», значит прокси хостинга подменяет заголовок `Host`. Сообщите об этом: проверку нужно будет настроить под конкретный хостинг.

## Что НЕ публиковать

`private/` (хеш пароля и ключ 2FA), `data/radar_data.csv` (названия компаний и ФИО индивидуальных предпринимателей), исходные `.xlsx` хакатона, папку `backup/`, старый однофайловый `index.html` (в нём **встроены** данные 759 компаний), скриншоты с ключом 2FA.

Если ключ 2FA или файл `auth.json` случайно попали в git или в чат, запустите `setup_2fa.py` заново (новый ключ и пароль) и обновите переменные на хостинге. Удаления файла из репозитория недостаточно: он остаётся в истории.

## Данные: что настоящее, а что нет

- **Координаты, адреса, ИНН, ОКВЭД** взяты из листа `МОД1_Таб1` файла хакатона (759 компаний). Для части компаний координаты приблизительные, по центру населённого пункта (колонка `approx = 1`, в карточке есть пометка).
- **Статус клиента, выручка, динамика** — в исходных данных этих полей нет. Карта показывает «нет данных», а «белые пятна» не вычисляются, пока нет статусов.
- **Модуль 2:** проекты взяты из листа `МОД2_Таб1`. Стадия, отрасль и ИТ-потребности вычислены по описанию проекта.
- **Модуль 3:** коэффициенты и цены взяты из листов `МОД3_Таб1–Таб4`. Кнопка «Скачать КП (.docx)» — демо: файл не создаётся.

### Как добавить реальные статус и выручку

Заполните в `data/radar_data.csv` колонки (разделитель — `;`): `status` (`active` / `действующий` / `клиент` или `potential` / `потенциальный`), `revenue` (выручка, млн руб.), `growth` (динамика, %). Пустая ячейка означает «нет данных». Строки без `lat`/`lng` на карту не попадают.
